# Задание 3 · Конвейер Optional для ночной смены

## Постановка

Дано (блок «дано» в `src/Task3.java`): реестр смен — у каждого инженера
своя смена со своими метриками. `findShift(engineer)` возвращает
`Optional<Shift>`, `findPeak(shift)` — `Optional<Metric>` пиковой
(самой медленной) метрики смены, `pageOf(host)` — ссылку на регламент.

Реализуйте:

```java
static String describeShift(String engineer)
```

— хост пиковой метрики смены, приведенный к странице регламента; при
отсутствии смены, метрики или страницы — строка `"нет данных"`.
Конвейер `flatMap`/`map`/`orElse` — **без единого `if != null`**.

Порядок работы: сначала соберите конвейер без условия по задержке,
затем добавьте `filter` — контроль проверяет финальную версию:
учитываются только метрики с задержкой свыше 100 мс.

Сценарии контроля:

| Инженер | Что в данных | Ожидается |
|---|---|---|
| anna | смена есть, пик 120 мс | `runbook/db-1.prod` |
| oleg | смена есть, пик 80 мс — отфильтруется | `нет данных` |
| irina | смена есть, метрик нет | `нет данных` |
| boris | смены нет | `нет данных` |

## Указания

- `findPeak` возвращает `Optional` — обычный `map` дал бы
  `Optional<Optional<Metric>>`; нужен `flatMap`.
- Условие «задержка свыше 100 мс» — это `filter` **до**
  `map(Metric::host)`: после `map` у вас `String`, а предикат — про
  `Metric`.

## Контроль

```
javac -encoding UTF-8 -d out src/*.java
java -cp out Task3
```

При правильном решении:

```
OK   смена anna (пик 120)
OK   смена oleg (пик 80, отфильтруется)
OK   смена irina (метрик нет)
OK   смены нет (boris)
```

## Дополнительно

Верните `Optional<String>` вместо строки-заглушки и обсудите, что
меняется для вызывающего: отсутствие снова становится типизированным.
