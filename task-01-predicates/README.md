# Задание 1 · Композиция предикатов для метрик

## Постановка

Дано: 7 метрик ночной смены (см. `src/ShiftData.java`) и порог
`THRESHOLD = 100`.

1. `slow()` — предикат «задержка **не менее** порога»;
2. `prod()` — предикат «хост заканчивается на `.prod`»;
3. `slowProd()` — конъюнкция условий, **одним выражением** через `and`;
4. `fastOrStaging()` — отрицание медленного **или** префикс хоста
   `staging-`, **одним выражением** через `negate`/`or`;
5. количество метрик, удовлетворяющих каждому предикату, — контроль в
   `main` уже считает его циклом; реализуйте предикаты и запускайте.

## Указания

- «Не менее» — это `>=`, а не `>`.
- Пункты 3–4 — про композицию: никаких вложенных `if` в теле лямбды,
  только `and`, `or`, `negate` над уже готовыми предикатами.
- Порог в лямбде — захват переменной: помните про effectively final.

## Контроль

```
javac -encoding UTF-8 -d out src/*.java
java -cp out Task1
```

При правильном решении:

```
данные: 7 метрик, порог 100
OK   slow
OK   prod
OK   slowProd
OK   fastOrStaging
дополнительно: slowProd + fastOrStaging = 6, размер списка = 7 — объясните расхождение
```

## Дополнительно

Объясните, почему сумма счетчиков `slowProd` и `fastOrStaging` не равна
размеру списка: условия одновременно **пересекаются** (одна метрика
подходит обоим) и **не покрывают** список (метрики `cache` не подходят
ни одному). Проверьте объяснение по данным `ShiftData`.
