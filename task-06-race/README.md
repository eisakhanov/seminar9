# Задание 6 · Параллельная сводка и исправление гонки

## Постановка

Дано: 100 000 метрик, генерация `ThreadLocalRandom` (блок «дано» в
`src/Task6.java`); «медленные» — задержка свыше 500.

1. `collectRacy` — параллельный поток; собрать хосты медленных метрик в
   **общий** `ArrayList` через `forEach` — намеренная гонка;
2. сравните размер результата с ожидаемым количеством медленных метрик
   (контроль выполняет три прогона) и объясните расхождение;
3. `collectSafe` — тот же результат корректно: `map` +
   `collect(Collectors.toList())`;
4. измерьте время последовательной и параллельной версий
   (`System.nanoTime`) — TODO 3 в `main`.

## Указания

- Гонка недетерминирована: расхождение видно на нескольких прогонах;
  возможен и `ArrayIndexOutOfBoundsException` из внутренних механизмов
  `ArrayList` — контроль перехватывает и печатает его.
- `Collections.synchronizedList` устраняет потерю элементов, но не
  делает решение корректным по структуре — и съедает выгоду
  параллельности.
- О корректности нельзя судить по одному прогону.

-- гонка: три прогона --

OK   safe.size

`safe.size` обязан сойтись с ожидаемым количеством точно.

## Дополнительно

Объясните, почему `filter + map + collect` масштабируется на любое число
потоков, а `forEach + add` — нет: независимое накопление частей и слияние
готовым `combiner` против общей разделяемой структуры.
