# Задание 2 · Мини-стрим: конвейер Pipeline

## Постановка

Настоящий Stream API появится в части 3 — а пока соберите его
упрощенную версию: класс `Pipeline<T>` с fluent-цепочкой ступеней.

Дано: каркас класса в `src/Pipeline.java` (конструктор, `from`,
`toList`) и метрики смены в `src/ShiftData.java`.

Реализуйте четыре ступени:

1. `filter(Predicate<T>)` — новый конвейер из элементов, прошедших
   проверку;
2. `map(Function<T, R>)` — новый конвейер из преобразованных элементов;
3. `reduce(U init, BiFunction<U, T, U> op)` — свертка в одно значение;
4. `countBy(Predicate<T>)` — количество прошедших проверку —
   **через `filter` и `reduce`**, без нового цикла.

Пример готового конвейера (заработает после реализации):

```java
List<String> hosts = Pipeline.from(metrics)
        .filter(m -> m.latency() > 100)
        .map(Metric::host)
        .toList();
```

## Указания

- Каждая ступень возвращает **новый** конвейер; сам объект не
  изменяется — в контроле один `shift` обслуживает все проверки.
  Настоящий `Stream`, в отличие от вашего конвейера, одноразовый.
- `reduce` на пустом конвейере обязан вернуть `init`.
- Почему `BiFunction<U, T, U>`, а не `BinaryOperator`? Типы
  аккумулятора `U` и элемента `T` различны — `BinaryOperator` требует
  совпадения.
- Пока ступени не реализованы, они бросают
  `UnsupportedOperationException` — контроль печатает
  `FAIL ... реализуйте TODO`.
